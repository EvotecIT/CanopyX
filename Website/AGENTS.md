# Agent Guide: canopyx.dev

## Purpose

`Website/` builds https://canopyx.dev with PowerForge.Web. The live demos on the site are generated by CanopyX itself from `tools/SiteDemos`, so the site always shows the current runtime.

## Build

```powershell
pwsh Website/build.ps1 -Serve            # dev pipeline + local server on :8080
pwsh Website/build.ps1 -CI               # CI-mode pipeline (engine lock, verify baseline, audit, optimize)
```

The optimize step must leave `live/` alone: its JavaScript minifier also rewrites the JSON data blocks in those pages (`0.01` becomes `.01`, which no JSON parser accepts). `htmlExclude` in `pipeline.json` only takes an array; PowerForge ignores a plain string or an `exclude` key without a warning.

The pipeline's first step (`config/presets/pipeline.demos.json`) runs:

```powershell
dotnet run --project Website/tools/SiteDemos -c Release -- Website
```

It writes `static/live/`, `data/demos.json` and `themes/canopyx/partials/generated/`. These outputs are ignored by git; never edit them by hand. The file explorer bundle is more than 100,000 nodes (about 40 MB across a few hundred files), so keep it out of commits.

Enabled features: `docs`, `notFound`. Fonts (Schibsted Grotesk, JetBrains Mono) and Prism are self-hosted with their licences; the site makes no third-party requests.

## Sources of truth

- `content/pages/`: home, demos and 404 pages.
- `content/docs/`: getting started, JavaScript and delivery guides. Keep them aligned with the repository README and `docs/`.
- `data/views.json`: the view catalogue. Families (with their tone), views (name, example, API, demo page, docs link), the capabilities every view shares and the packages. It drives the sidebar, the home workbench and catalogue, and the view pages. A new view is one entry here, a page in `content/views/`, steps in `data/tour.json`, its demo in `tools/SiteDemos/ViewDemos.cs` and its snippets in `tools/SiteDemos/Views/`.
- `tools/SiteDemos/Gallery/gallery.json`: the curated demo gallery of each view page, by example page name with a title and a one-line description taken from the example's own summary. SiteDemos runs the `CanopyX.Examples` program into a temporary folder, copies the listed pages (and their `-dark` variants) to `static/live/gallery/` and writes `data/gallery.json`. Keep the gallery to pages that are self-contained single files.
- `content/pages/compare*.md`: comparisons with other libraries. They exist so people searching for alternatives can find CanopyX, so titles use "<library> alternative". Stay respectful: no "better than" claims. Each states its check date, links its sources and says when the other library is the right choice. Recheck competitor facts when editing a page, and never guess at one.
- `data/home.json`: home page copy. Claims must match the README, `docs/` and the generated demos.
- `tools/SiteDemos/`: demo generator. It links the examples it shows from `CanopyX.Examples` (the file tree, change views, calendars, matrices and flows) instead of copying them.
- `themes/canopyx/`: layouts, partials and CSS. `partials/theme-tokens.html` also sets the `--cx-*` variables that theme the embedded static tables.

Demo iframes are same-origin; `assets/site.js` sets `data-cx-theme` on their grid hosts so they follow the site theme.

## Baselines

`pipeline.baseline.json` regenerates `.powerforge/{seo,verify,audit}-baseline.json`. Fix new findings before regenerating; baselines are for issues that cannot be fixed in this repository.

## Validation

Run the CI-mode pipeline and check the home, demos and docs pages at desktop and phone widths in both themes, including the theme of each demo frame. A local build does not prove that canopyx.dev has deployed the change.

## Design system

- **The shell.** Every layout includes `partials/header.html`, `partials/site-sidebar.html` and `partials/footer.html` inside `.cnx-shell`; their styles are global (`base.css`, `nav.css`). The header holds the brand, the items of the `main` menu in `site.json` and the actions, with icons for GitHub and Discord rather than words. Views and Docs open a panel (`.cnx-menu`): every view by family from `data/views.json`, and every documentation topic with the packages. Pages run at full width; only documentation pages keep the documentation tree (`partials/docs-sidebar.html`) down the left. On narrow screens the header's menu button opens the whole sidebar (views, documentation, packages) as a sheet. The current page gets the selected-row treatment (tint and a 2 px accent bar).
- **Views.** Every view has a page at `/views/<id>/` (`content/views/<id>.md` with `layout: view` and `meta.view: <id>`): the live demo, then "Build one like it" (`partials/view-code.html`, tabs from `data/viewcode.json`) beside the steps from `data/tour.json`. A view with more than one demo lists them beside the frame (a scrolling row of tabs on narrow screens). The demo frame fits short pages (`site.js` sets `--cnx-fit`). For long pages, its height limit follows the viewport height minus 120px, with a 560px floor and a 980px ceiling; the page scrolls inside the frame. `/views/` (`content/views/_index.md`, `layout: viewsindex`) is the catalogue; `/demos/` redirects to it.
- **Docs topics** come from the Docs group of the `main` menu: `Meta.thumb` names a render in `data/docs.json`, `Meta.group` places the topic on the docs map, `Meta.api` lists what the reader writes.
- **Output next to code.** Docs snippets live in `tools/SiteDemos/Docs/DocsSnippets.cs` between `// docs:begin <id>` and `// docs:end`; SiteDocs runs them and writes `data/docs.json`, live pages under `static/live/docs/` (sharing `static/live/assets/`) and static renders under `partials/generated/docs/`. Pages show them with `{{< cnx-example id="..." caption="..." >}}`, `{{< cnx-render id="..." >}}` and `{{< cnx-modes >}}`. Captions are plain text without `>`.
- **Tabs** use `.cnx-tabs` / `.cnx-tab` (with `.cnx-tabs--code` on dark code surfaces): grid column headers with a sort indicator on the selected tab.
- **Full-screen pages** under `/live/` get the site's slim bar from `LiveBar.cs`; inside a frame the bar hides and `site.js` themes the grid.
- **Type.** One family: Schibsted Grotesk, heavy and tightly tracked for headings; `.cnx-display` only goes larger and heavier (the home hero and the closing call to action). JetBrains Mono is for code and API names.
- **Colour.** Graphite surfaces and one indigo accent (`--cnx-accent`); indigo is none of the status colours the views draw, so chrome never reads as a state. One tone per view family (`--cnx-tone-explore`, `-plan`, `-compare`, `-guide`, `-deliver`, shown with `.cnx-tone`). Tones say which family a view belongs to and nothing else.
- **The home stages.** Two live stages sit under the hero and are the page's bold elements: the same change records in four views (`partials/sections/oneview.html`, `data/home.json`), then the workbench of every view over the code that builds it. Keep the rest of the page quiet.
- **The showcase.** `/showcase/` frames a complete report written by `tools/SiteDemos/Showcase/ChangeWeek.cs`, which also writes the home stage's pages. It is the one place the site tool references ChartForgeX; the CanopyX packages never do.
- **Motif.** Chevrons, guide lines and elbows from an expanded tree; the selected-row treatment marks the current item. Avoid all-caps eyebrows, gradient washes, entrance animations and arrows appended to link text.
